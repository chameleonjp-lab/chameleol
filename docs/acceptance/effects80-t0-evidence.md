## 実装範囲

- `src/presentation/scope.js`：画面ごとの有効性、単調な有効時間、同じキーの予約置換、解除の一度だけ実行。
- `events.js`：既存の判定状態をコピーして読む `PlayView` と表示イベント。判定状態・採点・履歴は変更しない。
- `catalog.js`：採用80件・除外20件と表示上限の定義。演出本体は後続工程。
- `src/app.js`：開始受付を最初の await より前に作成し、選択・再試行・保存・舞台への引継ぎまで同じ completion を保持。通信再試行では既存 requestId と launchId を維持する。
- 画面を離れた時に本編購読、予約、結果の遅延ベスト音、開始／終了演出の予約フレームを解除。古い非同期の舞台生成・保存確認・再開応答を取り付けない。
- ゲーム中の描画はゲーム時刻差だけで進める。開始／終了／結果の時計は独立し、visibilitychange によりフレームが止まる非表示時間も除く。
- ゲーム中のお知らせも同じ表示時計で動かし、離脱時に除去する。簡易表示も同じ表示イベント口を持つ。

DB_VERSION、保存キー、rulesVersion、generatorVersion、decorationVersion、historyFormat、通信形式、判定・入力規則、15言語の解決処理、実行時依存は変更していない。

## テストの再現と修正

| 条件 | 修正前 | 修正後の確認内容 |
|---|---|---|
| 音声準備／開始保存を遅延させて連打 | 受付が2回（期待1回） | 同じ受付を返し、保存・開始通知が1件 |
| 結果画面の再プレイ連打 | 共通ガード未実装 | 結果からも同じ受付を維持 |
| 名前あり開始の遅延／再試行／無名切替／取消 | 既存動作を回帰確認 | requestId・launchIdの維持、古い応答の放棄、次の開始可 |
| 保存失敗後に開始通知保存を遅延 | 受付の寿命を回帰確認 | memoryOnlyでも舞台への引継ぎまで受付を維持 |
| 開始応答待ちに別タブが開始 | レビューで検出、既存試験が時間切れ | 保存済みプレーの確認後に開始、各プレーの秘密を維持 |
| 保存済みプレーの再開待ちに再度開始 | 同じ受付／completionを維持できず | 所有権取得と舞台への引継ぎまで同じ受付 |
| 保存可能性の確認中に別画面へ移り、遅れて失敗 | 古い容量不足ダイアログが1個出る | 新画面に古いダイアログを出さない |
| 一時停止・非表示・復帰 | ゲーム時刻は既存仕様を維持 | 表示時刻も停止し、非表示時間を加算しない |
| ベスト音の前に結果画面を離れる | 従来のsetTimeoutが残る | 離脱後のベスト音は0回 |
| ゲーム画面を離れる | 購読解除の接続がない | 古いsession購読0、予約の実行0 |
| お知らせの有効時計・破棄 | scopeのtickでは終了せず | 有効時間で終了、破棄後の更新0 |

scope・表示時計の単体試験は未実装による失敗を確認してから実装した。
独立レビューの重要指摘2件と、遅い保存確認の指摘1件は、それぞれ失敗する回帰試験を確認して修正した。
