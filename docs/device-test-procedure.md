## PR #26の標準手順（2026-11-17）

現在の候補と確認状況は[実装・検証・配布候補の記録](acceptance/pr26/completion-task4/evidence.md)を参照してください。PR #26のオンライン候補URLはまだありません。現在の本番を候補として試さず、確認済みのHTTPS候補URLが用意されてから始めます。パソコンや同じWi-Fi、履歴・サイトデータの削除は必要ありません。今ある成績・途中保存を残してください。

1. **版を記録します。** iPhone 17 ProのSafariで案内された候補URLを開きます。日付、iOSの版、候補URL、同じ候補の `release.json` にあるcommitとassetVersionをメモします。本番の版との違いは[比較票](release/pr26-candidate-comparison.md)で確認します。別の候補URLでは保存場所も分かれるため、既存成績が見えないだけで消えたと判断しません。
2. **表示と操作を確かめます。** 縦・横、アドレスバーが伸びた時と縮んだ時、文字を大きくした時に開始・停止・再プレイとパレットが使えるか確認します。練習から4つのガイドを開き、本編の19→20、39→40、49→50棟も届いた範囲で記録します。結果カードの下の補足が読めるか、模型と回転パネルが1つずつ開くか、横操作で回転し縦操作でスクロールできるかも試します。
3. **画像の共有と保存を確かめます。** 結果の主共有ボタンを押し、共有先にXがあれば、投稿画面へ結果画像が1枚添付されたか確認します。公開投稿は不要で、確認後に取り消して構いません。取消後に勝手に本文画面が開かないか、明示的な保存操作で表示した画像を長押しして保存できるか、訂正・回転・言語変更後に古い画像が残らないか確認します。Xが表示されない・添付されない場合はその状態を記録し、成功とはしません。
4. **音・中断・読み上げを確かめます。** 音あり/なし、別アプリへの切替、画面のロックと復帰、停止と再開、「動きを減らす」を試します。音や舌がまとめて連発しないか、再開できるか確認します。VoiceOverで結果、共有、保存、閉じる、再プレイを順に読み上げ、保存中に背面のボタンへ移動しないかも記録します。10回の再プレイで操作不能や古い画面の残りがないか確認します。
5. **気づいたことと未測定を残します。** 画面録画・スクリーンショットと、発熱、かくつき、操作の遅れ、言語を記録します。15言語の自然さは母語話者の確認と分けます。iPhoneだけで正確な描画間隔やメモリー値を取得できない場合は「未測定」と書いてください。録画の見た目や自動ブラウザの値で性能合格を代用しません。

性能は基準版/追加版を同じ条件で各30秒測り、描画間隔の95百分位33.4ms以下、中央値の悪化10%以内を目標にしています。同じ入力や温度をそろえられない比較、正確な値を取れない場合は、操作感の記録までに留めます。初回読込もデータを消さず、開き直しにかかった時間として記録します。

## 準備

パソコンと iPhone を同じ Wi-Fi につなぎます。パソコンで次を実行すると、検証用のゲームが作られて、同じ Wi-Fi の端末から開けるようになります。

```sh
npm ci
npm run build
node scripts/serve.mjs --root dist --host 0.0.0.0 --port 5173
```

iPhone の Safari で `http://<パソコンのIPアドレス>:5173/` を開きます。この形では順位の通信先がないため、名前の登録や順位は「つながっていない」表示になります。通信まで試す時は、検証用の Supabase を用意して `KAMEREORU_API` を指定して作り直します（`docs/release/release-and-rollback.md` の「1. 検証環境で通す」）。

ホーム画面の下にある「検証メニュー」を使うと、20棟目の手前、終了の手前、夜の場面から始められます。50棟を毎回はじめから遊ばなくても、明るさの解放やクリアの演出を確かめられます。このメニューは本番用には出ません。

## 確かめること

計画書 P9 の項目を、次の5つのまとまりに分けて試します。結果は下の記録表に書きます。

1. **画面の形**：縦向きと横向き、短い縦の画面（402×700 に近い大きさ）、アドレスバーが伸び縮みした時、画面の上下の切り欠き（安全領域）で、パレット・明るさのバー・警戒の表示が隠れたり重なったりしないか。15言語のうち長い訳（ドイツ語、ロシア語など）でも文字があふれないか。
2. **指の操作**：2本の指でパレットとバーを同時に動かせるか。片方を離してももう一方が続くか。指を置いてから色が変わるまでの遅れが気にならないか。画面のスクロールや拡大が起きないか。
3. **色の見え方**：壁と体の色が同じ値の時、iPhone の画面でも同じ色に見えるか。一致度85%（色差6）と55%（色差14）の境目が、「同じ／少し違う／明らかに違う」の感覚と合うか。暗い色と白に近い色で、合わせられるのに失敗と判定される組がないか。
4. **中断と保存**：ホームへ戻る、着信、画面を消す、別のアプリへ切り替える、Safari を強制終了する、通信を切る。それぞれの後で「つづきから」が保存した時点から再開できるか。音が止まり、戻った時に鳴り直すか。
5. **長く遊ぶ**：3回続けて遊んだ時に、読み込みが遅くならないか、本体が熱くならないか、画面がかくつかないか。

## 測って記録する値

追加演出80件の確認は `docs/acceptance/effects80-evidence.md` の各No.へ記録します。検証版の強制表示で開始・中間・終了を確認し、採用80件と除外20件を混ぜません。402×700、402×874、874×402でガイド4段階・結果・19→20棟・46→50棟の画面を保存し、パレット・バー・停止が押せることも確認します。

iPhone 17 Pro Safariでは、装飾あり／なしを同じseed・入力・温度条件で比べます。ウォームアップ後、開始直後と最終地区を各30秒録画・計測し、フレーム間隔の中央値と95百分位を残します。目標は95百分位33.4ms以下、装飾ありの中央値悪化10%以内です。基準版自体が目標を超えた場合は両方の値を残して合格を保留します。10回連続の再プレイで描画物体数と購読・予約・古い画面への更新を確認します。SafariでJSヒープが取れない場合は「未測定」と書き、物体数をヒープの値に置き換えません。自動Chromiumの数値は実機の合格根拠にしません。

| 値 | 測り方 | 記録 |
| --- | --- | --- |
| 初めて開いた時の読み込み時間 | 旧案のデータ削除を使う測定は実施しない。保存データを残した読込時間を上の現行手順へ記録する | 未測定 |
| 操作の遅れ | 指を動かしてから色見本が変わるまでを、画面録画のコマ送りで数える | 未測定 |
| 保存の間隔 | 遊んでいる途中で強制終了し、再開した時に何秒戻ったか | 未測定 |
| 操作履歴の最大の大きさ | 検証メニューの結果画面、または送信した記録の大きさ | 未測定 |
| 発熱・描画のかくつき | 3回連戦の後の本体の温かさ、かくつきの有無（主観でよい） | 未測定 |

## ホームの色変化・巻きベロ（2026-11-14追加）

対象は[ホーム演出の検証記録](acceptance/home-idle-evidence.md)に記した実装版です。iPhoneだけで開ける実装候補URLは未用意です。旧公開版をこの変更の確認先として扱わず、候補が用意されたらURL・コミット・`release.json` の `assetVersion` を記録してください。既存成績を保つため、この確認でサイトデータを削除する必要はありません。

1. iPhone 17 Pro Safariで402×700、402×874、874×402相当の縦横表示とアドレスバー伸縮を確認します。模型枠内側8 CSS px以上に頭・尻尾・輪郭・最大長の舌が収まり、開始・練習・設定の操作を妨げないことを確かめます。
2. ホームを30秒表示します。緑から始まる滑らかな色循環、初回2〜3秒後と以後6〜10秒の休止を挟む巻きベロを録画します。先端がほどけて戻る形、直線との接続、口への収納、色の連続性を記録します。
3. 舌の予備・伸長・収縮・収納中に設定・遊び方・練習・本編へ移動し、ホームへ10回戻ります。古い模型が重ならず、毎回緑から始まり、操作できることを確認します。
4. 別アプリへ切り替えてから戻り、停止位置から再開し、溜まった動作が連発しないことを確認します。
5. iOSの「動きを減らす」を表示中にも切り替えます。有効時は舌が収納され向き・顔の動作が止まり、体色は続くこと、解除後6〜10秒待って再び舌が動くことを確認します。
6. 30秒連続表示と10回再表示後のかくつき・発熱・操作感を記録します。自動Chromiumの結果をSafariの合格に置き換えません。
