# 同系色タイムアタック：敵対的検証と修正記録

更新日：2026年11月21日（日本時間）  
対象：[完成版要件仕様書](../superpowers/specs/2026-11-21-chameleol-time-attack-spec.md)と[実装計画書](../superpowers/plans/2026-11-21-chameleol-time-attack-plan.md)。

## 1. 結論と検証範囲

仕様と計画を別担当が独立に読み、誤った記録・二重集計・状態の競合を起こす具体例を作って検証した。指摘を両文書と実装後の試験へ反映し、修正箇所を再レビューした。**今回の文書レビュー範囲で、未解消のCritical／Important指摘はない。** 軽微な補足も反映済み。

ゲームやサーバーの新機能を実装して試験した記録ではない。実施したのは、現行ソースとデータ構造の読み取り、提案した色候補の全組合せ計算、称号と時間の算術検査、文書間の照合、独立レビューである。実装後の動作・通信・iPhone実機・本番公開の確認は計画T1〜T9の作業として残す。

## 5. 実際に行った数値・文書検査

### 5.1 色候補を全件検査した結果

固定コミットの `src/rules/v1/color.js`、`detmath.js`、`config.js` を変更せず使い、各系統651色の全組合せを比較した。目標同士の明度は10000にそろえ、既存の色差式で90%未満の次候補数を数えた。

| 系統 | 候補色数 | 条件に合う次候補数の最小 | 候補がなくなる色 |
| --- | ---: | ---: | --- |
| 赤 | 651 | 503 | なし |
| 緑 | 651 | 101 | なし |
| 青 | 651 | 427 | なし |
| 明度 | 21 | 14 | なし |

色の比較は各系統211575組、3系統計634725組（自己比較と向きの重複を除く）。明度は前後の差1000以上を条件に確認した。独立した2担当の計算が同じ最小候補数となり、取りまとめ担当も保存されたスクリプトを再実行して照合した。

この検査が示すのは出題候補の存在であり、3系統の人にとっての難しさが等しいことではない。また「前の目標との一致90%未満」は、前棟を95%で終えた任意の操作値が次棟で必ず95%未満になる保証でもない。仕様§3でこの範囲を明示した。

### 5.2 時計と称号

| 確認項目 | 結果 |
| --- | --- |
| 必須保持 | 30×500＝15000ms |
| 移動 | 29×2000＝58000ms。30棟目後の移動なし |
| 停止と調整を除く所要時間の下限 | 15000＋58000＝73000ms。公式記録には58000msを含めない |
| 最速称号の上限 | 15秒＋20秒＝35秒。3500cs以下 |
| 称号数 | 58。最初1500〜3500cs、次から10秒幅、最後59500超〜60000cs |
| 端の値 | 14999msは切上げ前に無効。35000msは第1、35001msは第2。600000msは第58、600001msは称号なしの完走 |
| 重複・抜け | 段階1〜58と日本語称号名が一意。1500〜60000csを重複なく覆う |
| 最大値 | 9007199254682991＋58000＝9007199254740991。履歴tを安全な整数に保つ |

10分超は順位へ登録できる。8MiB/64片/200000イベントの履歴上限は別の運用条件であり、超過時はゲームを強制終了せず、端末結果と未登録理由を残す。再送・予約の期限として10分を使わない。

### 5.3 文書としての完了確認

54要件の番号、58称号、18群の受入条件、T0〜T9の担当を照合した。新しい文書同士とREADMEの相対リンク、Markdown表の列、見出しとコードブロック、文字列の不整合を確認した。ゲームと実験場の正確な変更先、現行の実行コマンド、追加する試験、公開順と切戻しを計画へ記載した。

会話で揺れた保存先は「既存Supabase内の専用表」、計時は最新説明に合わせ「一時停止・自動移動を除く」に統一した。「確認したい5点」の欠落を、未提示の選択肢が承認されたものとして扱っていない。ユーザーの追加指定「移動2秒」は仕様・計画・数値検査のすべてへ反映した。

## 6. 実装時に確認を残すこと

色の体感難易度、実際の2秒移動と表示待ち、iPhone Safariの縦横・ロック・共有画面は、コードがないこの段階では確認できない。サーバーの入力履歴再計算は規則との整合検査であり、人の操作を証明する機能ではない。一時停止中に記憶した色を考える行為や、自動入力を完全に防げるという主張もしない。

本番の追加表・専用経路・定期処理・TAタブはまだ作成していない。文書PRのマージを機能公開と誤認せず、実装後にA01〜A18の証拠を集め、T9の順番で公開する。
