## 最初に遊べるもの

最初の試作では、iPhoneでパレットを動かし、次の壁に合わせて体色を変え、警戒されずに何棟進めるかを試せるようにする。ここで「同じ色に見えるのに失敗する」「片方の指を離すともう一方も止まる」といった問題を先に見つける。その後、本編の演出・練習・中断再開を組み込み、同じプレイをサーバーでも再現できた段階で順位の登録をつなぐ。

**出発点。** main `a3bed0d` には README・仕様・受入試験・仕様レビューの4ファイルがある。ゲーム、素材、テスト実行環境、データベース変更、公開用の設定はこれから用意する。本計画のパス・関数名・工程の分け方は実装案である。

**採用済みの条件。** 本編は全50棟、通過した棟の平均を使う。20棟目で明るさ操作を導入する。練習は3問。名前は任意で、整理後に同じ名前は1枠に集める。順位は通過棟数、次に小数2桁の平均一致度で決める。30位の同順位者は全員表示する。ほかのゲームの名寄せや件数上限をそのまま使わない。

**技術の分担。** 画面は静的なHTML・CSS・JavaScript、街とキャラクターはThree.jsを第一候補とする。得点・出題を決める小さなJavaScriptモジュールは画面や通信から切り離し、端末とSupabaseの検証処理で同じ版を読む。色の換算、配点、保存周期、通信上限など[仕様第19章](../specs/2026-11-07-kamereoru-design.md)の値は試作値として管理する。

### P1　ゲーム内の時計で、出題と採点を再現する

- [ ] `package.json` でJavaScriptをモジュールとして読み込めるようにし、`src/rules/v1/` の `engine.js`、`color.js`、`course.js`、`config.js` と `tests/rules/*.test.mjs` を作る。先に時刻つきの色入力と期待結果を用意する。`makeCourse(seed, generatorVersion)` は50棟の目標色、`advance(state, event, rules)` は次の状態と確定した通過・発見等の出来事を返す。描画速度・音・端末の現在時刻を計算に入れない。
- [ ] 初期設定は1棟5秒。各棟の入口から `[1.5秒, 4.5秒)` を評価し、5秒の出口で1回だけ確定する。前の時刻からの時間を評価開始・終了・通過・警戒100到達の各点で分割する。同じ時刻では直前までの積算→発見の確定→区間・通過の処理→受信順の色変更と進める。猶予にも操作は反映し、警戒と平均はそこで止める。長い処理停止は自動停止へ送る。
- [ ] 色合い・鮮やかさ・明るさの選択値から壁と体の論理色を作る。色の違いを測る候補式（CIEDE2000）と一致度への換算を分け、完全一致が100%、差が広がれば非増加、色差6・14と瞬間状態・平均85%の関係を記録する。換算候補の検算表を先に作り、実機確認まで確定させない。
- [ ] 建物ごとに「一致度×有効時間」を積算して時間で割る。85%の連続成功は丸め前、正確さ点は棟ごとに整数へ四捨五入。順位用の値は通過棟の丸め前の平均をさらに平均し、最後に0.01%単位の整数へ四捨五入する。0棟では平均は空値。警戒は0から始めて持ち越し、100で発見。毎秒の警戒増減は仮に−35／＋12／＋45、通過20・正確さ最大80・連続最大20・クリア200の初期配点を設定から読む。成功3／5／10棟で上がった加点段階は成功が続く各棟に適用する。
- [ ] 色の乱数と装飾の乱数を分ける。1〜19棟は明るさ100%で作れる色、20〜22棟は小さな明暗変化、終盤には大きな明暗の交互変化を入れる。同じ番号・版で同じ50色、装飾変更で色順が不変になることを試す。候補生成には試行上限と、その段階の制約を満たす代替色を置く。固定した複数の番号で明暗差・操作距離・似た色の連続数を集計し、実機調整に渡す。

**端末とサーバーの計算をそろえる。** 試作ではゲーム内時刻を1ミリ秒の整数、同時刻の入力を発生順の整数で表す。操作値は色合い0〜35,999、鮮やかさ・明るさ0〜10,000の整数に写し、その値で表示・採点・記録する。色から得る瞬間一致度の精度は仮に1%の100万分の1とし、色差の参照例と閾値前後で両側が同じ整数になることを確認する。積算は整数の積と時間の分数のまま保持し、十分な桁数で計算する。警戒100に初めて届く刻みで停止し、評価終了と重なれば発見を先に確定する。長い停止とみなす間隔も設定に含め、跨いだ時間を加算しない。実測で精度を変える場合は記録形式・判定版・照合例を一緒に更新する。

**出題の合否。** 1〜19、20〜22、23〜29、30〜39、40〜50の帯ごとに、生成前に許容する色・操作移動量・明暗交互回数を仮設定として記録する。固定シード0〜999を使い、全5万棟で操作値から目標色への往復が一致し、各帯が設定内に収まることを確認する。候補を全却下させても、前棟との制約を満たす代替列で終了することを試す。体感の難易度と許容範囲はP2の実機評価で調整する。

**完了を決める例。** 1秒95%＋2秒75%で建物平均は245/3%。3棟が92・81・87なら86.67%。84.999%はコンボ未達、85.000%は達成。順位用の75.085%は整数7,509（表示75.09%）。全体平均を十進の規則で四捨五入し、浮動小数の積をそのまま丸めない。50棟すべて100%なら仮配点で6,080点。249.5秒から250秒未満で途中終了すれば49棟、250秒ちょうどの終了操作では出口通過を先に処理して50棟で確定する初期案とする。評価終了・発見が同時の場合、異なる描画間隔、色差の既知の正解例も含め、`node --test tests/rules/*.test.mjs` で確かめる。

### P2　iPhoneで色を合わせられる本編を作る

- [ ] `index.html`、`src/app.js`、`src/ui/controls.js`、`src/ui/screens.js`、`src/ui/game.css` を作る。ホーム・開始・本編・停止・再開・結果をつなぐ。壁と体の比較面は仮の図形でよい。現在の壁と次の壁を見せ、上にステージ、下に左の円と右の縦バーを配置する。通過数・得点・数値を隠した警戒ゲージを表示し、本編の一致度は言葉や表情で伝える。
- [ ] タッチごとに押し始めた部品を記憶する。円外は外周、バー外は端、遠く外れたら最後の値を保持し、戻ると追跡を再開する。別の指は先の指を奪わない。中断・画面離脱で指の割り当てだけを解放し、黒から戻しても色合いを保つ。開始時の固定プレビューと白黒のマーカーは入力を遮らない。
- [ ] 仮設定では開始後94.5秒で19棟目の評価が閉じ、20棟向けのバーを操作できる。95秒で20棟目に入った時だけ明るさ練習を永続解放し、96.5秒で20棟目の評価を始める。バーと円は移動させない。初回の遊び方、警戒が上がった時の説明、19棟の予告と「切替OK」、ホームからの再視聴を用意する。
- [ ] `tests/ui/controls.test.mjs` とiPhone 17 Pro Safariの縦・回転で確認する。片指順次／2本同時／片指離し／3本目／端外／タッチ中断を試す。開放直前で終了した新規端末では練習がロックされ、開放後に再挑戦した本編では再びバーがロックされる。P3以降で使う画面はこの入力部品を共有する。

**画面と次工程への引き渡し。** ホームには名前の任意入力、はじめる・つづきから・練習・ランキング・設定・あそびかた・送信状況の入口を置く。停止画面では再開・音設定・やり直し・ホームへを選べる。結果画面は終了理由、通過数・平均・得点内訳・最大コンボ、もう一度・ホームを持ち、後で自己ベスト・順位・送信状態・上位一覧・共有をつなぐ。P2で `src/storage/store.js` に解放と初回案内の保存口を作り、P4で中断位置と同時に保存する形へ拡張する。未接続の機能は検証用と分かる表示にする。

実機担当にはiPhoneから開ける検証用URLと、通常開始・19→20棟・最終出口を試せる手順を渡す。境界を短時間で試すための準備済み履歴は検証用に分離し、正式な開始受付や順位登録へ送れないことも確かめる。

**完了の証拠。** 同じ設定色の壁・体・プレビューを昼・夜・ライト点灯中に並べた画面、最大2人追跡時の操作、連戦前後の描画物体数とメモリ傾向、実機で聞いた通知音の結果を残す。

### P4　練習・一時停止・保存を両立させる

- [ ] `src/practice/session.js` は基本／明るさの各3問を簡単→標準→難しい順に出し、同じ色判定を使う。時間制限は設けず、最初は緑、次問は直前の色・部品位置を保持する。出題時点の体色がすでに成功域にある候補は除き、試行上限後も同じ難度で成功域外の目標を選ぶ。各問で指を触れずに待っても成功しないことを試す。成功の維持時間は約0.5秒を試し、最初の成功時間を固定しつつ最高一致度は問題終了まで更新する。現在値の表示切替、成功後の「次へ」、スキップ時の最後の色と目標色の比較を分ける。
- [ ] 3問を処理した回だけ、両種類合わせて直近2回を残す。全問スキップも完了、途中終了は保存済み履歴に加えない。操作後の終了だけ確認し、答え合わせ・停止中は時間を計らない。本編の回数・自己ベスト・中断位置に触れない。
- [ ] `src/storage/store.js` に端末の複数の値を一緒に書き込める保存機構（IndexedDB）を置く。本編の番号・名義・版・乱数・時計・猶予・色・警戒・評価中の積算・確定済みの棟・得点・コンボ・解放状態・操作履歴の末尾を同じ世代で保存する。通過時、一定間隔、停止時に保存し、周期と失い得る進行幅を実測する。設定・練習・送信待ちは別に保つ。
- [ ] `src/app.js` で画面非表示を停止扱いにし、壁を覆い、音・入力・ゲーム時計を止める。復帰は本人の再開操作とカウントダウン（仮3秒）を経る。途中から新規開始する場合は確認し、旧プレイの確定分を終了待ちへ保存してから次へ進む。破損・未知版は隔離して理由を示す。空き不足で自動整理するのは再取得可能なものだけ。進行中の書込失敗は警告してメモリで続行し、可能なら終了送信する。

**保存が競合する時。** 本編ごとに、現在の書込担当タブ・世代・状態を同じ保存処理内で照合してから更新する。別タブが引き継ぐ時に所有世代を進め、古いタブの保存や終了を通さない。終了は確定済み結果と履歴を未送信欄へ追加する操作、進行中欄を終了済みにする操作を一取引にまとめる。対象外プレイはローカル結果へ移す。95秒の古い保存が新規開始後に返っても、終了済みの欄や新しいプレイを上書きできない。失敗時は以前の確定保存を残し、旧結果を保全できるまで同じ欄を使い回さない。

**完了の証拠。** `tests/practice/session.test.mjs` と `tests/storage/resume.test.mjs` で、2タブ・猶予中と通過前後の強制終了、終了取引の書込失敗、全問スキップ後の次回途中終了を再現する。整理では進行中・未送信・照会情報・音量・言語・解放・端末内ベストを保護し、練習履歴は本人の確認を経て消す。実機では停止中と再開カウント中に壁色が読めず、入力・時計が止まること、保存不能時の警告で再起動による喪失が伝わることを確かめる。

### P5　登録名と、通信が途切れても取り違えない開始受付を作る

- [ ] 既存の実験場・サーバーのゲーム識別値、受け付ける項目、閲覧範囲、開始回数の数え方、読み取り先を実装時点で読み取り確認し、`docs/integration-contract.md` に記録する。実験場の[カタログの確認版](https://github.com/chameleonjp-lab/chameleonjp_lab/blob/70bfea7fbf856dbc139f2ef90b2a641db646d693/catalog/games.json)の38件にはカメレオるの項目がない。対象の記録や契約がほかにあるかは未確認。確認前の作業はローカルの代替受付で行い、既存の識別値・他ゲームの表を流用する前に互換性を試す。
- [ ] `src/shared/name.js` を端末・サーバーで共用する。「名前を入力すると、名前と記録がランキングに公開されます。空欄でも遊べます。」と伝える。生入力のバイト数・改行・危険な方向制御を先に検査し、全半角を含む表記の整理（NFKC）、前後の空白除去、連続空白の圧縮を行う。整理後も形式・バイト上限と見た目20文字を検査し、保存予定名を表示する。整理と文字区切りは同じUnicode版に固定し、21文字は切らず訂正を促す。絵文字や各言語に必要な結合は残す。公開の集約キーは整理後の文字列をバイト単位で区別し、大小・アクセントまで同一視する照合設定を使わない。名前は文字列として挿入し、文字の方向を行内に閉じ込める。
