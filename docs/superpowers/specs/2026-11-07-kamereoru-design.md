## 1. 目的と基本仕様

宝石を盗んだカメレオンが、建物の色に体色を合わせて警察から逃げるスマートフォン向けブラウザゲーム。移動やジャンプではなく、**色を見て、自分で同じ色を作ること**を主な遊びにする。

| 項目 | 最新の採用内容 |
| --- | --- |
| ゲーム名 | カメレオる |
| 本編 | 全50棟。50棟目を完全に通過するとクリア |
| 通過時間 | 1棟5秒を試作基準とする。合計250秒＝4分10秒。開始・終了演出と停止時間は別 |
| 移動 | 自動で右へ進む横スクロール。ジャンプ・攻撃・移動操作なし |
| 色操作 | 左の円形パレットで色合い・鮮やかさ、右の縦バーで明るさ |
| 縦バー | 1〜19棟は灰色の「未開放」。20棟から操作可能 |
| 色変更 | タップ・ドラッグに即時反映。決定ボタン・長押し微調整・正解への自動補正なし |
| 指操作 | 1本指の順次操作と、2本指の同時操作の両方に対応 |
| 出題 | 毎プレイ、難易度条件付きで色と組み合わせをランダム生成 |
| 難易度 | 進行に応じて配色・必要操作量を変える。後半は明→暗→明→暗の大きな変化を重視 |
| 警戒 | 不一致で上昇、擬態成功で低下。棟をまたいで持ち越し、100で発見 |
| 警察 | 最大2人のフェレット。通常は画面外、警戒度に応じて接近 |
| 本編の一致度表示 | 数値を隠し、状態の言葉・表情・動作・音で知らせる |
| 練習 | 1回3問、時間制限なし、スキップ・途中終了可能 |
| ランキング | 通過棟数が多い順。同棟数なら平均一致度が高い順の1種類 |
| ランキング精度 | 平均一致度を小数点以下2桁へ四捨五入して比較・表示 |
| 名前 | 任意。内容自由、世界各地のUnicode文字・絵文字、見た目の文字単位で最大20文字 |
| 集計単位 | 整理後の登録名ごと。同名の別人も同じ枠に集約する採用仕様 |
| 言語 | サイノメと同じ15言語。ランキングは全言語共通 |
| 保存 | 本編自動保存・中断再開、未送信結果保全、練習履歴は直近2回 |
| 運用 | 専用管理画面なし。自動検証を基本とし、必要時のみSupabase Dashboardで確認 |

## 4. 画面と進行状態

**UI-01** 縦画面のiPhone Safariを主対象とする。上部は横スクロールステージ、下部は左パレット・右バー。比率は固定の60:40とせず、実機で操作面積と視認性を両立させる。

**UI-02** カメレオンは中央よりやや左でほぼ固定。現在の建物と次の建物を同時に見せる。警察官は左の画面外から接近し、判定対象の壁や体色を大きく隠さない。

**UI-03** 本編と練習でパレット・バー・色プレビュー・カメレオンの基本位置を共通にする。練習ボタンを増やすためにパレットだけを縮小しない。

| 画面 | 主な情報・操作 |
| --- | --- |
| ホーム | タイトル、カメレオンと街、任意の名前、はじめる、つづきから、練習、ランキング、設定、あそびかた、記録の送信・確認状況 |
| 本編 | 通過棟数`n / 50`、総得点、警戒ゲージ、一時停止。連続成功数は通過時のみ短く表示 |
| 操作部分 | 白黒の縁を持つ選択マーカー、明るさ位置、固定の現在色プレビュー。プレビューは最終的な体色と一致 |
| 一時停止 | 再開、音設定、最初から、ホームへ。やり直し・ホームは途中終了の確認を行う |
| 再開準備 | カウントダウン後に保存位置から再開。建物・判定・入力は停止 |
| 結果 | 終了理由、棟数、平均一致度、総得点と内訳、最大連続成功、名前に対応する自己ベスト・順位、送信状態、上位30位、もう一度、ホーム、Xでシェア |
| 練習 | `1 / 3`等、状態表示。上部に一致度を見る・終了、ステージとパレットの間にスキップ・次の問題 |
| 記録確認 | 未送信、確認待ち、再審査、修正内容を区別。一覧は新しい順で全件へ到達可能 |

**UI-04** 警戒ゲージは上部の横棒。数値は表示せず、長さと「警戒中」「危険！」等を併用する。色変更の猶予中はゲージを消さず、現在の長さを保持する。

**UI-05** 「切替OK」は猶予中を知らせる文字と短い音で示す。猶予外も色の操作は可能だが、警戒・得点判定の対象になる。ボタン・通知は壁とパレットの視認性を優先する。

本編の状態は、ホーム→開始準備→初回演出（該当時のみ）→進行中↔一時停止→再開カウントダウン→進行中→終了確定→終了演出→結果、と区別する。送信・審査状態は画面の状態とは別に管理し、結果の送信待ちで次のプレイを止めない。

## 5. 50棟・境界・時間の契約

**TIME-01** 50棟を自動通過する。1棟の区間は5秒を基準とし、全棟で同じ長さにする。後半も速度・警戒増減・色差基準を勝手に厳しくしない。建物の装飾的な幅や高さを変えても、判定用の1棟の通過時間は変えない。

**TIME-02** 境界の基準は、アニメーションで揺れないカメレオンの胴体中心に対応するゲーム上の基準点。尻尾・手足・振り返りで切替時刻を変えない。2棟の色を混ぜた中間色は正解にしない。

**TIME-03** 境界前後に合計約2秒の猶予を設ける。初期案は境界の0.5秒前から1.5秒後。猶予では警戒上昇・回復と平均一致度の集計を両方停止する。歩行と色操作は続ける。

**TIME-04** 前の棟の集計は猶予開始時に締め、新しい棟の集計は猶予終了時から始める。ただし「通過棟数・得点・連続成功の確定」は物理的な通過境界で1回だけ行う。集計を締めただけでは通過として数えない。

**TIME-05** 50棟目の出口を越えた時点だけをクリアとする。出口前の発見・途中終了では50棟目の得点とクリアボーナスを付けない。51棟目は出題しない。

### 5.1 初棟・最終棟の補完案

各棟の入口から出口までを5秒とし、全棟共通の評価区間を入口後1.5秒〜出口前0.5秒の3秒とする初期案を置く。1棟目の開始後1.5秒は初回の準備猶予、最終棟の最後0.5秒はゴールへの移行猶予として扱う。これにより全50棟の評価時間がそろう。初回説明の有無で判定時間を増減しない。

通常の境界では、前棟の最後0.5秒＋次棟の最初1.5秒が連続した猶予になる。最終棟の評価を締めてから出口に届くまでに手動終了した場合は、未通過のため49棟までを記録する。初棟・最終棟の配分は試作時に再確認し、正の評価時間と同じ計算規則を保つ。

### 5.2 境界で重なる処理

補完案として、評価区間は開始を含み終了を含まない区間で管理する。同時刻の色変更・区間終了・通過を処理する順序を端末と検証側で共通化する。前区間の警戒・一致度を先に確定し、その時点で発見条件を満たした場合は次の通過やクリアを先取りしない。フレーム飛びでも同じ順で処理する。

停止中・再開カウントダウン・開始演出・終了演出の時間はゲーム内経過時間に含めない。画面の更新回数だけで速度・平均・警戒を決めない。長い処理停止が起きた場合は突然大量に時間を進めず、安全に停止する初期案とし、処理方式を端末・再検証で一致させる。[S3][S4]

## 6. 色操作の契約

**INPUT-01** 円の角度で色合い、中心からの距離で鮮やかさを選ぶ。中心は白寄り、外周は鮮やか。右の縦バーは上が選択色そのまま、下へ行くほど暗くする。色合い・鮮やかさ・明るさを分けるHSV方式を候補とする。

**INPUT-02** 試作範囲は明るさ100%〜0%。1〜19棟は100%固定で、この条件で再現できる色だけを出す。「100%」は調整値であり、全色が人の目に同じ明るさに見えるという意味ではない。

**INPUT-03** 体色は入力に直ちに反映し、意図的な遅延・補間・正解への吸着を入れない。指を離しても最後の値を保持し、再タップは触れた位置を直接選択する。長押しモード・拡大パレットは作らない。

**INPUT-04** 各指は操作開始時にパレットかバーへ割り当て、離すまで対象を変えない。片方を離してももう片方を続ける。同じ操作部品へ追加された指は先の操作を奪わない補完案とする。2本指タップを一時停止へ割り当てない。

**INPUT-05** 円外では円周へ制限し、指の方向に合わせて色を選び続ける。バー上下外では端値で止まる。大きく外れた場合は最後の値を保持し、戻れば再開する。許容距離は調整値。指が他方の操作領域へ入っても対象を切り替えない。

**INPUT-06** 指の中断、画面離脱、再開時は保持中の接触を解除し、値だけを残す。操作範囲を出ても同じ指を追跡する仕組みを使い、ブラウザ操作と競合する制御は必要な操作領域に限定する。[S3]

**INPUT-07** パレット・バーの位置とサイズは途中解放で変えない。暗さ0%から戻したときにも、それまでの色合い・鮮やかさを復元できるよう各値を保持する。プレビューとマーカーはタッチを奪わない。

## 7. 色差・平均一致度・警戒度

### 7.1 色差から一致度へ

**COLOR-01** 建物の外壁の基本色1色と、選択された体色を比較する。窓、看板、屋根、陰影、警察、ライト、遠景は判定対象外。色差の計算には人の見た差に近づけるCIEDE2000を候補とするが、採用式・変換・係数は試作で確定する。

**COLOR-02** 色差から0〜100%の一致度へ変換する式はゲーム独自の規則であり、標準の百分率ではない。完全一致は100%、差が増えると一致度が下がる。警戒判定と一致度・得点が食い違う別々の換算を使わない。

初期目安は、色差6以下を擬態成功、6超〜14以下を少し目立つ、14超を危険。換算式を決める際に擬態成功境界と85%の関係を明記する。これらの数値・式を正式な公平性の条件とするのは試作検証後である。

**COLOR-03** パレット、プレビュー、カメレオンの比較に使う面、建物の壁は同じ色管理を使う。昼夜や環境照明で正解色が見かけ上ずれない。画面全体への色調整・発光を判定面へ適用しない。立体感は形状や比較を妨げない部位で表す。

### 7.2 建物単位の平均

**CALC-01** 棟iの有効な判定時間をT_i、その時間内の一致度をm(t)とし、建物平均A_iを「一致度×その状態が続いた時間」の合計÷T_iで求める。猶予・一時停止・演出・再開準備は除外する。描画フレームごとの値を単純平均しない。

**CALC-02** 途中終了・発見時の未通過棟は、平均・通過数・得点・連続成功の確定から除外する。通過棟に85%未満の棟があっても、全体平均には含める。

### 7.3 警戒

**ALERT-01** 警戒度は0〜100で、初期0。棟の切替でリセットしない。初期調整案は、擬態成功で毎秒35減少、少し目立つで毎秒12上昇、危険で毎秒45上昇。0未満・100超にしない。

**ALERT-02** 判定区間中に100へ達すると発見確定。警察との接触、懐中電灯の描画、スポットライトとの重なりは別の失敗条件にしない。

**ALERT-03** 警戒の初期段階例は30で1人、70で2人。ゲージ・表情・足音・警告は同じ警戒度を参照する。登場と退場の条件に幅を持たせ、境界付近で点滅的に切り替えない。人数、接近、音の違いで危険を伝え、色だけに頼らない。

## 8. 得点と連続成功

**SCORE-01** 総得点はゲーム内の達成表示として残すが、ランキング順位に使用しない。1棟の初期配点は通過20点＋正確さ最大80点＋連続成功最大20点。

**SCORE-02** 正確さの点数は`最大正確さ点 × A_i / 100`に比例させ、棟ごとの得点確定時だけ整数に四捨五入する。平均一致度や成功判定を得点の丸めに合わせて変えない。

**COMBO-01** 通過棟のA_iが**丸め前の値で85%以上**なら連続成功数を1増やし、未満なら0へ戻す。警戒度や瞬間的な成功音とは独立して判定する。過去の得点は差し引かない。

| 今回通過後の連続成功数 | その棟の追加点の初期案 |
| --- | --- |
| 1〜2 | 0 |
| 3〜4 | 5 |
| 5〜9 | 10 |
| 10以上 | 20 |

これは「3・5・10棟で加点段階が上がり、以後その段階の点を各成功棟へ加算する」方式であり、その3回しか加点しない方式ではない。節目の特別音は各連続記録の節目で1回だけ。配点・上限は調整値。

**SCORE-03** 50棟目の通過得点・連続成功を確定後、固定のクリアボーナスを1回だけ加算する。200点は旧会話からの初期候補であり確定配点ではない。保存復元・終了演出スキップ・再送で再加算しない。

**SCORE-04** 84.999%は85%へ丸めて成功にしない。結果の表示上85.00%になる場合でも、成功／未達の表示が実際の判定と逆転しない説明を添える。

## 9. 出題・街並み・難易度

**GEN-01** 全プレイヤーの出題順は固定しない。毎プレイ別の再現用番号（シード）と、版を固定した生成規則で色を生成する。同じ番号・規則・初期状態から同じ出題を再現できることを検証する。

**GEN-02** 色は、その時点で解放済みの操作で必ず再現できる。1〜19棟は明るさ100%の範囲。最初の体色は提供資料の緑、最初の建物は序盤条件に合うランダム色で、自動擬態させない。

**GEN-03** 明暗差、パレットの必要移動量、バーの必要移動量、明暗交互の回数、似た色が続く回数などに条件を置く。一定区間ごとの難易度の分布をそろえ、乱数の偶然だけで極端に簡単・困難な並びにしない。単にHSVの明るさ値の差だけで見た目の難しさを断定しない。

**GEN-04** 後半は特に明→暗→明→暗の大きな変化を増やす。色を目で見分ける難しさと、2つの部品を動かす量を両方検証する。速度、猶予、警戒増減を同時に厳しくして難易度を二重に上げない。

50棟への再配分は次を試作案とし、20棟の操作解放以外の区切り・割合は調整する。

| 棟 | 色操作の難しさ | 街・時間帯の案 |
| --- | --- | --- |
| 1〜19 | パレットのみ。わかりやすい色から少しずつ変化 | 住宅中心、昼 |
| 20〜22 | バー解放直後。小さな明暗操作で学べる色 | 商店街へ移行 |
| 23〜29 | 色と明るさの組み合わせを増やす | 店舗中心、夕方へ |
| 30〜39 | 明暗差・色合いの変化を増やす | オフィス中心、夕方〜夜 |
| 40〜50 | 大きな明暗交互の変化を多く含める | 高層街中心、夜 |

**GEN-05** エリアの主役となる建物を中心に、住宅・店舗・オフィス等をランダムに混ぜる。約70:30は初期候補で、固定の必須割合ではない。色の難易度と建物の見た目の乱数は分離する補完案とし、装飾の追加で出題色を変えない。

**GEN-06** 手前の建物とゆっくり動く遠景で奥行きを作り、カメラは横方向に固定。現在と次の壁を見せ、判定対象の壁を広く取る。窓・看板・屋根は控えめにする。遠景、道路、空は昼→夕方→夜へ変わるが、比較面の色は変えない。

**GEN-07** 50棟の出題データは再現できる状態に保つ一方、描画物体を50棟同時に読み込む必要はない。見える範囲と近傍だけ生成・再利用し、通過物体の資源を整理する。

## 10. 20棟解放・説明・成功演出

**GUIDE-01** 1〜19棟もバーの場所を確保し、「未開放」を表示する。19棟で予告、20棟への切替時に解放音と「上：明るい／下：暗い」を短く表示。歩行を止めず、数棟だけ明るさを調整しやすい出題にする。

**GUIDE-02（補完案）** 操作できる猶予を削らないよう、19→20棟の「切替OK」が始まった時点でバーを操作可能にする。これは20棟向けの準備であり、19棟の得点は既に集計を締めている。永続的な明るさ練習の解放は、胴体基準点が実際に20棟目へ入った時点で保存する。

解放時は明るさ100%のままにし、既存の体色を勝手に変えない。再挑戦の本編は再び19棟までロックするが、一度解放した練習機能は残す。

**GUIDE-03** 初回は短い開始演出に続いて操作案内を出し、初めて警戒が上がったときに警察の意味を知らせる。2回目以降は初回案内を省略し、ホームの「あそびかた」で目的、操作、猶予、警戒、50棟、20棟解放を再確認できる。案内を見たことで順位条件を有利・不利にしない。

**FX-01** 擬態成功が短時間続いたら安心した表情と短い成功音。約0.2秒は調整値。同棟での成功音は原則1回とし、猶予中は新しい成功音を確定しない補完案にする。判定再開後から確認する。

**FX-02** 棟通過時はその棟の平均で連続成功を判定し、3・5・10の節目に別の短い演出を出す。一瞬の成功音が、その棟の成功・加点を保証する表示にならないよう区別する。

**FX-03** 節目は短い文字・音と街並みの変化で表す。50棟化に合わせ、20の解放、25通過の中間地点、40以降の終盤、50クリアを初期案とする。旧50中間・80終盤・100クリアは使わない。判定面を光らせず、パレットを隠さず、ゲーム中に大きなカメラ移動を入れない。

## 11. 音響

**AUDIO-01** 軽快でコミカルな背景音楽を控えめに繰り返し、エリア別の風・街・遠くの車などの環境音を加える。警戒度で別曲へ切り替える複雑な音楽システムは必須にしない。

**AUDIO-02** 警戒段階が上がると警告音、警察の接近に応じて足音の大きさと速さを変える。高警戒で2人の追跡を表し、離れると小さくする。境界付近で警告音を連発しない。

**AUDIO-03** 切替OK、擬態成功、連続成功の節目、操作解放、警戒、発見、クリア、結果、選択・決定・戻るを聞き分けられるようにする。通知時は音楽・環境音を一時的に下げ、重要音を聞き取りやすくする。細かな優先順と音量は試作確認。

**AUDIO-04** ホーム・一時停止・結果から共通設定を開く。背景音楽／効果音／環境音の3音量と全体消音を保存する。変更は即時反映、保存ボタンなし。消音解除は設定済みの音量へ戻し、0やオフを未設定と誤認しない。

**AUDIO-05** 明示的な開始・再開操作で音声利用を準備する。音声機能が使えなくてもゲーム・得点・保存は続ける。一時停止・画面離脱で音を止め、復帰時に過去の足音や警告をまとめて鳴らさない。停止中の設定変更だけで本編音楽を勝手に再開しない。

## 12. 練習モード

**PRACTICE-01** 1回3問。制限時間・警察・ゲームオーバーなし。得点・本編棟数・ランキング・本編プレイ回数へ加算しない。基本練習は最初から、明るさ調整練習は本編20棟到達後に利用可能。

**PRACTICE-02** 基本練習はパレットのみ、明るさ練習はバーも使用。各3問を簡単→標準→難しいの順で条件付きランダム生成。本編と同じ操作感・色差基準を使い、練習だけ甘い判定にしない。

**PRACTICE-03** 1問目は緑・明るさ100%から始め、以後は直前の体色と両部品の位置を引き継ぐ。スキップでも自動で正解色へ変更しない。次の色は、その練習段階内で現在色と違うものを選び、何もしなくても成功になる出題を避ける。

**PRACTICE-04** 成功状態を短時間保つと成功を確定する。約0.5秒は調整値。成功後も操作を続けられ、「次の問題」で進む。3問目は「結果を見る」。成功はその問題内で保持し、後で色を外しても最初の成功時間を取り消さない。

**PRACTICE-05** 「一致度を見る」で現在の数値の表示・非表示を切り替える。数値を見ることによる成功基準の変更はない。本編の数値非表示ルールは変えない。

**PRACTICE-06** スキップは可能。目標色と最後の選択色を並べて答え合わせしてから次へ進む。正解位置への自動変更はしない。比較中の最後の色の一致度と、過去の最高一致度を混同して表示しない。

**PRACTICE-07** 結果は各問の成功／スキップ、最高一致度、初めて成功した時間を表示。最高値はその問を終了するまで更新し、初回成功時間は固定する。停止・答え合わせ中は計測しない。未成功の時間は「—」。全スキップでも終了できる。

**PRACTICE-08** 成功後は「次の問題」を主操作にし、不要なスキップを重ねない補完案とする。成功前の進行はスキップで可能にする。1問について成功／スキップを二重に件数加算しない。

**PRACTICE-09** 3問分の処理が完了した練習だけを、基本・明るさ練習を合わせて直近2回保存。スキップで終えた問も3問の処理に数える。3回目で最古の1回を入れ替える。途中終了は履歴に追加せず、既存2回を消さない。

**PRACTICE-10** 操作開始後の終了は「練習を続ける／終了する」で確認。まだ操作していなければ確認なしで戻れる。練習結果からもう一度・本編・ホームへ進める。本編の中断データを練習開始・履歴整理で上書きしない。

## 13. ランキングと登録名

### 13.1 順位と自己ベスト

**RANK-01** 通算ランキング1種類。定期リセットなし。通過棟数降順、同棟数なら平均一致度降順。総得点、コンボ、クリアボーナス、終了時刻、プレイ回数は順位決定に使わない。

**RANK-02** n棟通過時の全体平均Mは`(A_1 + … + A_n) / n`。各棟を同じ重みで扱い、成功・失敗に関係なく通過した全棟を含める。未通過棟は含めない。棟の平均を先に丸めてから合計しない。

**RANK-03** 全体平均を最後に小数点以下2桁へ四捨五入し、その同じ値で表示・順位・自己ベストを比較する。保存上は0.01%単位の整数など、比較と表示をそろえられる形式を採用する。細かい内部値で同表示の順位を分けない。

例：50棟・92.35%は50棟・92.34%より上。49棟・99.00%は両者より下。92.341%と92.344%はともに92.34%として同順位。85%の連続成功判定はこの丸めとは別。

**RANK-04** 同じ棟数・同じ2桁一致度は同順位。1位が2件なら次は3位。**順位30位以内を全件表示**し、30位の同順位者を切らない。件数が多い場合は同じ順位表をページ分割してもよいが、対象者全員へ到達可能にする。「先頭30人」や「上位30種類の順位」へ置換しない。

**RANK-05** 自己ベストは実際の1回のプレイの組を保存する。別プレイの最大棟数と最高一致度を合成しない。棟数が増えたとき、または同棟数で2桁の一致度が上がったときだけ更新する。同じ組では更新しない。修正・承認順によって弱い記録へ下げず、受理済み全記録から再選定する。

**RANK-06** 0棟終了はプレイ回数のみ。平均は0%でなく未算出「—」、今回の順位はなし。過去の有効な自己ベストは維持する。通過1棟以上、名前あり、開始登録済みの本編結果だけを登録候補とする。

**RANK-07** 自分で終了しても確定済み棟の記録を送る。送信待ち・確認待ちの新記録は正式順位として表示しない。受付後に順位取得だけが失敗した場合、記録そのものを失敗扱いせず順位取得を再試行する。

### 13.2 名前

**NAME-01** ホームの名前は任意。空欄でも本編・練習・閲覧を利用できる。開始前に「名前を入力すると、名前と記録がランキングに公開されます。空欄でも遊べます。」と伝える。名前なしではランキング登録と今回の順位表示を行わない。

**NAME-02** 同じ整理済み登録名の記録を1枠へ集約する。ログインや個別プレイヤー識別を必須にしない。この仕様は本人確認ではなく、同名の他人の記録も混ざり得る。人数表示は実人数と誤認させず「登録名数」等を用いる。

**NAME-03** 名前を変更したら以後の新規プレイから新名を使い、過去記録を移動・削除しない。開始時の名前をそのプレイに固定する。再開・再送時は開始時の名前を維持し、後から匿名プレイを公開対象へ変えない補完案とする。

**NAME-04** 全角半角などの互換表記をそろえる処理（NFKC正規化）を行い、前後の空白を除き、連続空白を1つにする。大文字小文字、アクセント、別文字体系の似た字は区別する。NFKCは全半角以外も変えるため、保存予定名を画面へ反映し、変換を隠さない。[S1]

**NAME-05** 整理後の名前を、人が1文字として受け取るまとまりを近似する単位（書記素クラスター）で最大20文字とする。文字数カウンターも同じ規則。超過を勝手に切り捨てない。ブラウザとサーバーで同じUnicode版・規則を固定して試験する。[S2]

**NAME-06** 内容による禁止語・差別語等の自動審査、管理者による名前審査、通報、名前確認中／非公開への置換は作らない。ただし、改行・危険な制御文字・表示を壊す入力・異常に大きいデータは技術的に拒否する。空白だけは未登録として扱う。

**NAME-07** 世界各地の文字と正常な絵文字・結合文字を扱う。正当な言語や絵文字で使う不可視の結合文字を一律削除しない。文字数とは別に内部バイト数等の上限を試作で決める。名前は翻訳せず、プログラムとして実行せず文字列として表示し、右から左の名前が順位・数値の方向を変えないよう隔離する。

**SHARE-01** 結果画面から今回の確定結果と正式URLをXへ共有できる。自動投稿せず投稿画面を開き、開けない場合はコピーを案内する。共有文は選択言語で作る。未承認の記録を正式なオンライン順位として共有しない。公開URL・紹介画像は公開工程で確定し、本PRで架空の本番URLを設定しない。

## 15. 開始登録・送信・再送

### 15.1 開始

**NET-01** 名前ありのランキング対象プレイは、サーバーの開始受付が確認できた後に開始する。開始記録はプレイ番号、開始時の登録名、サーバー側受付時刻、出題再現番号、生成規則・判定ルール・ゲーム版を含める。再開で新しいプレイ番号を作らない。

**NET-02** 初回＋最大2回の自動再試行を行い、失敗後は「もう一度試す／ランキング対象外で遊ぶ」を選ぶ。再試行中も対象外プレイへ進める。間隔・待機上限は調整値。無限待機・無断で対象外へ変更はしない。

**NET-03** 同じ開始要求の再試行には同じ要求番号を使用し、同じ受付内容を返す。サーバー受付後に応答だけ失った場合も別プレイを量産しない。準備だけで中止した要求を完了記録として扱わない。

**NET-04** 最初から通信できないプレイは対象外で遊べるが、後から対象へ変えない。開始受付済みなら途中切断後も続行し、終了結果を後から送れる。名前なしの開始回数は結果と分離して重複なく記録し、通信不能を理由に遊びを止めない。

「オフラインで遊べる」は必要なゲーム資源が既に読み込めている場合の意味。未訪問状態からのオフライン初回読み込みを保証する仕組みは、本仕様の必須範囲に加えない。

### 15.2 終了と再送

**NET-05** 50棟クリア・発見・明示的途中終了で、確定結果と操作履歴を端末へ保全してから終了送信する。アプリ切替は終了でなく停止。操作履歴を各棟の通過ごとにオンライン送信する仕様にはしない。

**NET-06** 終了時のまとめ送信は1つの論理結果を意味する。容量に応じて分割転送しても、全片を受信・検証してから1回だけ受付完了とする。部分受信だけでランキング登録しない。

**NET-07** 通信失敗は端末に残し、起動時・通信回復時・手動操作で再送する。ブラウザを閉じた間の送信は保証しない。同じ結果番号で再送し、重複送信・順序逆転・応答消失でもプレイ回数と得点を二重に加算しない。

**NET-08** 未送信があっても別の新規プレイを開始できる。新規プレイ自身の開始受付は別途必要。未送信結果を新しい結果で上書きしない。保存容量不足時は第16章を適用する。

**NET-09** サーバーの完全受付確認後に端末の送信待ちを解除する。受付済みで検証中・確認待ちなら、その状態の照会へ移る。確認待ちと通信失敗を混ぜず、恒久的な登録拒否を無限に再送しない。再送対象が不正な1件に阻まれて他の送れる記録まで止まらないようにする。

**NET-10（補完案）** 再試行中に対象外プレイや新規プレイへ進んだ後、古い開始応答が到着しても現在のプレイに取り付けない。受付済みの元の要求は中止として追跡可能にし、元の記録や回数を重複させない。

## 16. 一時停止・自動保存・容量不足

**SAVE-01** 別アプリ移動・画面非表示で自動停止し、復帰だけでは再開しない。再開を押してカウントダウン後に進める。初期案3秒。停止・再開準備中は建物の色を隠す不透明な覆いを使い、色変更・判定・音の進行を止める。[S4]

**SAVE-02** 警戒、選択色、棟と区間内位置、猶予残り、評価積算、得点、連続成功、出題番号と乱数状態、解放状態、操作履歴の末尾、プレイ番号、開始時の名前と対象可否を整合した1つの保存単位として残す。異なる時点の情報を混ぜて復元しない。

**SAVE-03** 建物通過時と一定間隔で保存し、可能なら停止時にも保存する。強制終了直前のイベントだけに依存しない。保存周期は試作で決め、再読込で失う可能性がある進行幅を明示する。「必ず直前の瞬間へ復帰できる」と保証しない。

**SAVE-04** 途中のゲームがあるときは「つづきから」を表示する。新しく始める場合は確認して前プレイを終了し、保存できている確定棟だけを記録する。破損・未対応版の保存を勝手に初期化せず保護し、再開できない理由を知らせる。

**SAVE-05** 安全に再取得できるキャッシュと受信確認済み詳細履歴の端末コピーだけを自動整理する。未送信結果・操作履歴、進行中の保存、非公開記録の照会情報は自動削除しない。練習履歴の削除などは本人確認を伴う。

**SAVE-06** 容量を確保できない場合、新しいランキング対象プレイは開始させず、再送・整理・対象外プレイを選べるようにする。すでに進行中の保存失敗でゲームオーバーにしない。警告し、メモリ上の状態を保ち、可能なら終了送信する。ただし端末再起動等で失われ得る限界を隠さない。

**SAVE-07** 音設定・言語・初回説明済み・練習解放・端末内自己ベストを、未送信データの整理で消さない。新規プレイ開始時はゲーム状態だけを初期化する。

**SAVE-08** 機種変更・サイトデータ削除の復旧機能は作らない。サーバー上の正式記録・確認待ちを端末削除に連動して消さない。端末だけの未送信、途中プレイ、練習履歴、照会情報は復元できない。名前の再入力だけでは非公開データへアクセスさせない。

## 17. 不正検証・確認待ち・訂正

### 17.1 操作履歴

**VERIFY-01** 指の生座標をすべて記録せず、ゲームが判定に使った色・明るさと、そのゲーム内時刻または共通の計算ステップ番号を記録する。同値の連続はまとめてよいが、結果を変える色変更を間引かない。0.1秒ごとの粗い間引きは採用しない。

**VERIFY-02** 出題生成情報・版、初期状態、色の変化、境界と猶予、停止／再開、終了理由を照合できるようにする。採点外の猶予中も、後続の判定開始時点の色を正確に復元できる状態遷移を保持する。初期色と同時刻の変更順も再現する。

**VERIFY-03** 保存精度は本編計算と共通化する。端末側では高精度で採点し、履歴だけ粗く丸める方式にしない。圧縮は同じ順位・成功判定を再計算できる範囲に限る。

### 17.2 判定方針

| 条件 | 処理 |
| --- | --- |
| 棟数・順位用平均一致度が正しいと検証できた | 正式登録 |
| 順位用数値は正しいが補助履歴だけ軽微な不一致 | 正式登録し、不一致は内部記録。不要な警告を本人へ出さない |
| 不一致があるが既知の原因を再計算で解消できた | 正しい値を確定して登録 |
| 順位用数値の正当性を確認できない | 確認待ち。公開順位へ反映しない |
| 51棟・100%超など明確に成立しない入力 | 登録拒否。直ちに不正行為者と断定しない |
| 50棟・99.99%など高い値だけ | それだけで拒否・確認待ち・BOT扱いしない |

**VERIFY-04** 不一致箇所と前後の状態を調べ、必要なら後続へ再計算を伝播する。1棟だけ勝手に除外・0点化せず、警戒や終了時点への影響も確認する。回数・許容差は調整値だが、順位の0.01%、成功閾値、通過判定を曖昧な誤差として消さない。

**VERIFY-05** 当該プレイのルール版で検証する。同じ判定条件の再計算と、新しいゲームバランスへの置換は別であり、後者を自動訂正と呼ばない。

**VERIFY-06** 正しい履歴の再計算は、人間が操作した証明ではない。ブラウザ内の処理や履歴の偽造、自動操作を完全に排除できるとは説明しない。開始記録・制限・サーバー計算を組み合わせるが、残る限界を運用資料に残す。

### 17.3 確認待ちと再審査

**REVIEW-01** 自動再検証で解決できない場合だけ、管理者がSupabase Dashboardで確認する。ゲーム内／別サイトの専用管理画面、名前審査機能は作らない。

**REVIEW-02** 確認待ちの新記録は非公開にし、以前の正式な自己ベストを残す。問題がないと判断された記録は登録し、その時点の正式記録群から自己ベストを選び直す。

**REVIEW-03** 確認待ちは期限を理由に自動承認・拒否・削除しない。結果画面とホームから状況を確認でき、複数なら新しい順に全件へ到達できる一覧を用意する。少件数ずつ表示しても隠れた記録へ進めるようにする。

**REVIEW-04** 拒否された記録には1記録につき1回、送信元の確認情報を持つ端末から再審査を申請できる。再審査中も順位へ反映しない。管理者は申請の有無によらず明らかな誤判定を訂正できる。拒否理由・日時・変更前後を残す。

### 17.4 登録後の修正

**CORRECT-01** 明確な計算ミスで正しい値を確定できれば自動修正。不正の疑いだけなら管理者判断。推測で記録を削除しない。

**CORRECT-02** 各プレイの確定記録を残し、修正後に登録名の自己ベストと順位を再選定する。現在の自己ベストが修正で下がった場合、過去のより良い正常記録へ戻せる。別プレイの値を合成しない。

**CORRECT-03** ホームに「記録が更新されました」と示し、該当端末から変更前後・理由・現在の正式記録を確認できるようにする。強制ポップアップで開始を妨げない。公開ランキングには最新の正式値だけを出す。

## 18. データ・権限・保存期間

### 18.1 論理的に必要な情報

以下は情報の区分であり、テーブル名や関数名を指定するものではない。既存の実験場へ接続する場合は実際の契約を確認し、他ゲームの値や記録を変更しない。

| 情報 | 主な内容 | 公開範囲 |
| --- | --- | --- |
| 開始記録 | プレイ番号、要求番号、名前、受付時刻、再現番号、各ルール版、対象可否 | 非公開 |
| 最終結果 | 同一プレイの棟数、丸め前平均、順位用平均、総得点、終了理由、状態 | ランキング用の必要項目だけ公開 |
| 建物別集計 | 平均一致度、評価時間、通過、得点、連続成功 | 原則非公開 |
| 詳細履歴 | 時刻と判定色、停止・再開・終了等 | 非公開 |
| 正式自己ベスト | 登録名、採用した1プレイへの参照、順位比較値 | 公開 |
| 再送管理 | 結果番号、完全受信・処理状態、受付結果 | 認可された照会のみ |
| 審査・訂正履歴 | 元値、新値、理由、日時、再審査回数、判断者 | 必要範囲だけ該当端末／管理者 |
| 端末情報 | 設定、途中状態、練習2回、解放状態、未送信、照会情報 | 端末内 |

**DATA-01** 正式登録された集計結果は通算保存。詳細操作履歴は一定期間だけ保存し、30日は初期候補。確認待ち・再審査可能な拒否記録は必要な詳細を保持。再審査終了後の保持期間も調整値とする。

**DATA-02** 詳細履歴の整理と、プレイ集計・自己ベスト・訂正履歴・再送の重複防止情報の削除を同一処理にしない。詳細を消した後に同じ精度で再検証できるとは保証しない。無期限保留で容量が増える限界は記録し、無断で期限切れ拒否へ変えない。

**SEC-01** 名前だけでは非公開の開始記録・履歴・審査状況を閲覧・変更できない。公開のプレイ番号だけを知っていても同様。該当の送信元へ発行した推測困難な照会用秘密情報等をサーバーで検証する。具体方式は実装設計で選び、アカウント必須へ無断変更しない。

**SEC-02** クライアントは判定結果・承認状態・公開順位・訂正理由を自由に書き換えられない。必要なサーバー処理だけを許可し、データごとのアクセス制限（Row Level Security）と関数の実行権限を設計する。公開用キーは認証済み本人の証明ではない。管理用秘密鍵をブラウザ・公開リポジトリへ置かない。[S6]

**SEC-03** 操作履歴に位置情報・録画・他サイトの行動などを追加しない。照会用秘密情報や認証情報をログ・共有URL・公開ランキングへ載せない。文字列の表示とデータベース処理は、利用者入力をコードとして実行しない方式で行う。

**SEC-04** 大量送信への具体値は未決。初期案としてサーバーで開始頻度、同時要求、結果サイズ、履歴件数、再送間隔に上限を設ける。同じ要求の正当な再送を新規大量送信として数えない。登録名だけを理由に他人を締め出せる制限にしない。制限時も保存記録を捨てず、再送可能かを伝える。

## 20. 補完案と運用上の線引き

**DEFAULT-01 管理者通知：** 会話で通知方式の最終選択はない。初期仕様では自動メール・定期通知・外部通知サービスを作らず、必要時のDashboard確認とする。未審査を期間だけで拒否しない。定期タスクを本PRで作成しない。

**DEFAULT-02 大量送信：** 第18章のサーバー側制限を初期案とし、具体値は通常の連戦・復旧時の一括再送・共有回線で試験する。外部の有料対策や人間判定サービスは追加承認なしに導入しない。

**DEFAULT-03 開始・終了の競合：** タイムアウト後の遅延応答、二重タップ、再開中の新規開始、送信と名前変更が重なっても、操作の対象プレイを識別して取り違えない。開始名・ルール版・対象可否はプレイ中に変えない。

**DEFAULT-04 更新：** 正式公開後、順位に関係する色判定・棟数・通過時間・出題難易度・操作条件は原則固定。見た目や操作の変更も正確さへ影響する可能性を確認する。必要な大変更は旧記録を残して別途判断し、無断リセット・新式での一括再採点をしない。

**DEFAULT-05 既存サービス：** 本書はSupabaseの既存テーブル・関数・実験場の現在の契約を調査済みとはしない。接続情報・正式公開URL・既存ランキングとの接続方法は実装工程で確認する。秘密情報を本書へ転記しない。

**DEFAULT-06 素材：** 提供キャラクター資料を優先し、モデル・効果音・背景音楽の使用条件と出典を実装時に記録する。広告・課金・販売を前提にした機能は追加しない。有償素材を勝手に購入しない。
