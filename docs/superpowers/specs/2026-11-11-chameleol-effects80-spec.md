# カメレオる 追加演出80要件 確定仕様書

対象はゲーム中と結果画面の見た目を増やす80要件です。先に除外した20案を外し、残りはすべて実装する前提で確定します。「採用確定」は実装済みという意味ではありません。

作成日：2026-11-11。確認したコード：[`858a44263275`](https://github.com/chameleonjp-lab/chameleol/tree/858a4426327594a05ca810ee6156f8c2a0d5ad16)。既存の[基本仕様](2026-11-07-kamereoru-design.md)に対する追加仕様で、採点・保存・ランキングの契約は基本仕様を優先します。

## 1. 決定した範囲と優先順位

元のNo.を引き継ぎ、除外後の80件に優先順1〜80を付け直しました。利用する人数・効果・確からしさを作業量で割って比較するRICE評価を使います。式は `Reach × Impact × Confidence ÷ Effort`、人数は仮に30日・100プレイ、作業量は8時間を1人日とする仮見積もりです。実際の利用率や出現確率、処理速度、納期を示す値ではありません。

各数値、元100件内の順位、依存関係は[機械可読の対応表](../../requirements/chameleol-effects80.json)に残しました。独立した仮見積もりの合計を納期にはしません。表示の共通基盤・素材作成・結合確認は別に必要です。実装順は高い順位を優先しつつ、共通処理と依存先を先に作ります。

## 3. 記録の扱い

No.33・37は、猶予中にmatchUnitsがnullへ戻る現在の仕様に合わせます。既存のフレーム・色入力の処理直前に観測した評価中の成功状態を表示専用の真偽値lastEvalSuccessへ保持し、次の評価開始・次棟・終了で消します。表示のための真偽値で、得点の連続成功を推定し直しません。

新しい毎フレーム記録、警戒の時系列、画像の撮影、過去場面の再生は追加しません。No.78は既存のscoreの4内訳、No.82・83・89は既存summary.perBuildingの`[matchSum, evalMs, points]`を使います。通過済み棟だけを対象とし、棟別データは先頭50件までを扱い、tupleの欠損・長さ不正、evalMsが正の安全な整数でない値または3000超、matchSumが有限の非負の安全な整数でない値または100×unitsPerPercent×evalMs超なら表示集計から除きます。BigIntへの変換前に検証し、壊れた1件で結果全体を消しません。元の棟番号は除外しても詰め直しません。既存の署名対象・送信結果・判定規則は書き換えません。

最高・最低の比較は丸め前の分数をBigIntの交差積で比べ、同率なら小さい棟番号を採ります。地区平均は既存の`rankAverage`へ有効な棟の`{matchSum,evalMs}`を渡し、棟平均を等しい重みで平均して最後に1回だけ丸めます。地区は`areaOf`の現行5区分（1〜19／20〜22／23〜29／30〜39／40〜50）です。20棟ごとには分けません。

最後に到達した棟は`min(50, floor(endT / 5000) + 1)`です。No.93はこれで地区を選び、通過済み数だけから地区を決めません。No.89で到達地区に通過済みの有効データがなければ「成績なし」とします。0棟時は開始地区の背景とデータなしを示します。

No.92の目標色は終了直前に`session.game.course.targets`を最大50個コピーし、今回の結果表示用メモリだけで使います。再生成・入力履歴の走査・端末保存はしません。過去結果などコピーがない画面では「今回の色は表示できません」とし、異なる出題を推定して埋めません。

追加する保存は既存kvの`presentation.stats.v1`一つ、UTF-8のJSON換算で2048バイト以内です。保存形は次で固定します。

```text
{version:1, bestCombo:0..50, firstClearAt:null|epochMs,
  previousResult:null|{playId, buildings:0..50, rankAverage:null|0..10000,
    maxCombo:0..50, endedAt:epochMs}}
```

名前・秘密・seed・操作履歴・画像・出現IDは入れません。No.54は端末全体の記録、No.98は名前をまたぐ端末内直前1回と表示します。No.53・79の名前ごとの既存localBestとは混ぜません。No.85は初クリア日のみを保持します。既存の端末データは初期化しません。

playIdは既存の文字列IDを128文字以内で扱い、日時は有限の非負の安全な整数だけを許可します。初期値・不正値の正規化を先に行い、JSONサイズ確認で例外を出さないデータだけを書きます。

保存更新は`Store.endRun`の既存の終了取引内に任意項目として加え、終了権限が正しい時だけ最大1回行います。保存前の直前成績を今回の比較用として返し、同じ結果の再描画や言語変更では再更新しません。同じplayIdは重複扱い、遅れた結果で新しいpreviousResultを戻しません。bestComboは最大値、firstClearAtは最初の有効値を保ちます。壊れた追加データはこのキーの表示だけ初期状態にし、別の保存を消しません。追加データの検証失敗は得点の終了保存を止めません。保存全体が失敗した時は既存の失敗処理を使い、追加表示はその画面のメモリだけで完結させます。

## 4. 動きを止める条件と負荷の上限

ゲーム中の時刻はsession.state.tだけを使います。停止・再開待ち・非表示中は新規の動作を進めず、復帰時に経過分をまとめて再生しません。結果では非表示時間を除く画面内の経過時間を使います。終了確定後のNo.59・60にはゲーム用とは別のending scopeを作り、その画面で0から始まる経過時間と既存のスキップを使います。ゲーム時刻を渡した同じscopeへ0を渡し直しません。非表示時間は終了シーケンスの経過にも含めません。

画面ごとの管理対象を作り、離脱時に購読・入力受付・アニメーション・予約音・終了待ちをすべて止めます。開始を受け付けた時点でボタンを一度だけ処理し、No.99の演出完了を開始条件にはしません。非同期の順位取得・自己ベスト読込はplayIdと画面世代の両方が一致する時だけ表示を更新します。得点の保存・送信待ち・再送は表示の後片付けと分け、そのまま継続します。

新しい背景の小芝居は1プレイ最大6回、開始間隔15秒以上です。猶予に入った時に1回だけ抽選し、表示できなければ持ち越しません。候補はNo.12:15%、13:12%、14:15%、15:12%、16:10%、36:12%、61:3%、65:6%、70:5%、なし:10%。No.65は昼の地区だけ有効、無効な候補は「なし」にします。既存の出題乱数・装飾乱数を消費せず、表示専用の独立した乱数列を用意します。

| 対象 | 初期実装の上限・条件 |
|---|---|
| 描画 | 現在の画面のWebGL描画器は最大1個。結果は0個。街の7棟表示枠を維持 |
| 追加の静止装飾 | 同時24点以内。共用の形と画像を使い回す |
| 背景人物・乗り物 | 小芝居は同時1組。鳥の時だけ最大3羽をその一組に含む |
| 粒子など | 既存の星56・点56を拡張せず、追加の煙・葉・蒸気は合計8枚まで、成功の輪は1枚 |
| 描画の増加 | 同じ場面の現行比でdraw calls +12以内、geometries +16以内、textures +4以内を目標兼受入上限とする |
| 素材 | 追加圧縮画像合計1.5MiB以内、各画面で展開する追加画像16MiB以内。1024または2048pxの共用画像を使う |
| 結果の表示 | 逃走地図50マス、色50個、宝石10粒、実績3個、地区はがき5枚まで。数え上げは0.6秒 |

これらは計測済みの値ではなく、今後の実装で守る上限です。超えたら使い回しや画像化で修正し、80要件を無断で削りません。画面内の連続描画間隔が50ms超となるフレームが30回続いたら、その本編中は背景抽選を停止します。計数は一つの整数だけで、停止・非表示・長い処理停止でリセットし、次プレイで再判定します。背景以外の状態表示や数値は維持します。既存のWebGL不可時の簡易表示でも操作・成功状態・結果の数値は利用できます。

見た目の優先順は終了→危険→成功→節目→小芝居です。重なる低優先の動作は省き、1.5秒を超える待ち行列を作りません。動きを減らす設定では移動や点滅を静止状態へ置き換えます。減らした状態でも成績・状態変化の文字と数値は残します。

## 7. 画面・素材・文言の完成条件

ゲーム中は既存の円形パレット、明るさバー、一時停止、警戒表示を最優先に配置します。402×700では装飾札を短くし、重要な情報と入力領域が欠けないことを確認します。結果は主成績→再プレイなどの操作→補足のカード・はがき→既存ランキングの順にし、補足だけ縦スクロールを許可します。新しい横スクロールや自動送りの待ち時間は設けません。既存のX共有・ランキング・ホームへの導線を維持します。

新しい文言は15言語で用意し、絵の中に固定した日本語を焼き込みません。名前は既存の安全な文字表示を使います。数え上げ中の読み上げは最終値1回だけとし、色だけで通過・未通過を区別しません。装飾は原則aria-hidden、No.100だけ意味のあるボタン名を付けます。

結果の主人公は既存No.28モデルを元に制作時に書き出した画像を使用します。日中・商店昼・商店夕・オフィス夕暮れ・高層夜の背景5枚と、逃走成功・発見・中断・得意顔の主人公4姿勢を共用画像にまとめます。実行時の描画器追加・画像書き出しはしません。街と警察の追加素材も既存の配色・輪郭へ合わせ、`assets/credits.md`に出典を追記します。

## 8. 実装後の受入判定

80件の存在は抽選任せにせず、検証専用の固定条件で一件ずつ確認します。通常プレイでの出現頻度とは分け、証拠と元No.の対応を残します。固定条件は既存の検証環境だけで有効にし、本番のURL引数や順位送信へ混ぜません。

採点・送信データが同一入力で従来と一致すること、0棟・全50棟・同率・未送信・無名・保存失敗・古い保存・別タブ引継ぎを確認します。10回連続の再プレイでは前画面の音、文字更新、描画器、購読、予約処理が残らないことを確認します。実機性能は比較前後で同じ端末・同じ場面・同じ条件を使い、測定していないものを合格にしません。

この文書を追加するPRは計画のみです。実装後の検証結果は[既存の受入記録](../../acceptance/results.md)と[実機確認手順](../../device-test-procedure.md)へ実測結果として追記します。
