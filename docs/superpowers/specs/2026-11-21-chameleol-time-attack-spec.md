## 1. 決定の出所と適用範囲

ユーザーは、同系色の30棟タイムアタック、連続0.5秒の95%以上一致、15棟目からの明度、独立したランキングと開始回数、殿堂入りなしを指定した。保存先は「いま使っているSupabase内の専用テーブル」と明確化した。さらに本書の作成中に、**建物間の移動を毎回2秒**と指定した。

| 区分 | 本書での扱い |
| --- | --- |
| 明示された指定 | 上記のゲーム条件、開始位置、専用ランキング・集計、簡単な結果、タイムの称号、共有文を必須要件とする |
| 既に本文で示した推奨 | 開始時に1系統を抽選して固定、95%未満で保持リセット、名前ごとの最速1件、同タイム同順位、内部ミリ秒・表示2桁を引き継ぐ |
| 最新の説明で整理した計時 | 一時停止中と自動移動中は時計を止める。本書はこの方針を正本とし、旧要件案の「非表示中も加算」を取り消す |
| 本書で具体化した設計 | 色の数値範囲、同時判定、時間の切り上げ、同順位の並び、通信契約、10分超の扱い、15言語など。過去にユーザーが個別選択した内容とは記録しない |

## 3. 出題する色と初期値

### 3.1 色系統

色合い・鮮やかさ・明るさを別々の数値で持つ既存方式（HSV）を使う。色合いは1周を36000、鮮やかさと明るさは最大10000とする。以下は新しいTAルール第1版の固定値であり、通常用の出題規則を書き換えない。

| 要件ID | 条件 |
| --- | --- |
| TA-05 | 1プレイにつき赤系・青系・緑系を各1/3の確率で選ぶ。30棟を通して変更しない。名前ありはサーバー発行の乱数の元から決め、再送で引き直さない |
| TA-06 | 色合いは赤の中心0、緑12000、青24000から±1500、100刻み。赤は0をまたぐ範囲を正しく折り返す。鮮やかさは5000〜10000、250刻み。各系統651候補から選ぶ |
| TA-07 | 1〜14棟目の目標と操作値の明度は10000に固定する。15〜30棟目は5000〜10000、250刻みで目標を選ぶ。15棟目以降は前の目標明度との差が1000以上ある候補から選ぶ |
| TA-08 | 1棟目の主人公は無彩色 `h=0,s=0,v=10000` とする。次の棟では直前の操作値を引き継ぐ。色選択パレットは既存の全色を使い、目標だけを指定系統に限定する |
| TA-09 | 2棟目以降は、前の目標と色一致度90%未満になる候補だけを列挙し、その中から一様に選ぶ。抽選回数の上限で条件を破る代替色を出さない。色の選択と明度の選択を分ける |

同じ数値幅や初期値は系統ごとの偏りを抑えるための設計であり、人の見分けやすさまで完全に等しいという保証ではない。公開前に3系統の到達可能性と操作感を比較する。数値を変更する場合は、理由・測定・新しいルール版を記録し、公開済みの同じ版の意味を変更しない。前目標との90%未満という条件だけで、前棟を95%で終えたすべての操作値が必ず不一致になると断定しない。

### 3.2 クリア判定

| 要件ID | 条件 |
| --- | --- |
| TA-10 | 色一致は既存の `matchUnits` と同じ色差計算を使い、比較する両色の明度を10000にそろえる。明度差を色一致に二重加算しない |
| TA-11 | 明度一致の内部値は `100000000 - abs(v-targetV) × 10000`。1%は1000000。95%以上は明度差500以内を意味する |
| TA-12 | 1〜14棟目は色一致が95000000以上。15〜30棟目は色一致・明度一致の両方が95000000以上。この状態が**同時に連続500ミリ秒**続いた時点でクリアする |
| TA-13 | どちらかの必要条件が95%未満になったら保持を0へ戻す。表示用の丸めを判定に使わない。94.999999%を合格にしない。95%ちょうどは含める |
| TA-14 | 各棟で保持を新しく始める。前棟の余りや、途中停止前の499ミリ秒を持ち越さない。同一時刻の入力も受け付けた順番で処理し、一瞬の条件外れを圧縮して消さない |
| TA-15 | 30棟目の500ミリ秒成立時に完走と記録を確定する。31棟目や完走後の移動を作らない。警戒度・警察・棟ごとの制限時間による失敗や得点ボーナスは設けない |

時刻を進めてから、その時刻の入力を順番に適用する。499ミリ秒時点で条件を外せば失敗し、500ミリ秒時点まで成立していれば、その後の入力によって成立済みの棟を取り消さない。2つの条件を500ミリ秒ずつ順番に合わせる方式ではない。

## 4. 計時・2秒移動・一時停止

### 4.1 公式記録に含める時間

| 要件ID | 条件 |
| --- | --- |
| TA-16 | 1棟目の目標が表示されて操作可能になる開始境界から、30棟目の保持成立までの**操作可能な時間**を計測する。色を考えている時間と500ミリ秒の保持は含める |
| TA-17 | 1→2棟目から29→30棟目まで、移動は各2000ミリ秒とする。移動は29回、計58000ミリ秒。移動中は公式時計と保持を停止し、入力を受け付けない |
| TA-18 | 移動中は次の目標を隠す。隣の建物や比較見本、3D表示と代替表示も同じ条件にする。次の目標を見せること・操作を許すこと・その棟の計時開始を同じ境界で行う |
| TA-19 | 開始前の準備・説明・開始演出、完走後の演出・保存・通信は公式記録に含めない。30棟目の成立時刻を送信完了時刻で置き換えない |

2秒は、止めていない移動演出の実行時間を指す。画面非表示や一時停止が重なれば、その間は移動の残り時間も止め、復帰後に残りを進める。「動きを減らす」を選んだ場合は静かな表示へ置き換えてよいが、2000ミリ秒の移動区間と29回という回数は変えない。

描画が遅れた場合に、まだ表示していない次の棟で時間・保持を進めない。500ミリ秒成立や移動完了の境界で処理を止め、状態と表示の切替を確認してから次を進める。一度の大きな時間差で複数の棟を自動クリアさせない。

### 4.2 停止と復帰

| 要件ID | 条件 |
| --- | --- |
| TA-20 | 手動の一時停止、画面非表示、ロックで時計と保持を止める。保持は0にする。停止画面で現在・次の目標と比較色を隠し、色・明度入力を無効化する |
| TA-21 | 戻っただけでは自動再開せず「再開」操作を待つ。再開まで目標を隠す。再開は同じプレイとして扱い、開始回数を増やさない |
| TA-22 | 描画・入力・非表示通知・手動停止に共通の時計処理を使う。前回の確認済み更新から1000ミリ秒を超えて途切れた場合は、時間を足す前に自動停止する。未観測区間を操作時間や保持に足さず、記録済み時刻へ逆戻りもしない |
| TA-23 | ページの再読み込み・終了後のTA途中再開は第1版の対象外とする。開始回数と送信待ち記録は残し、途中のTAは未完走とする。新しい挑戦は新しい開始1回として扱う |

公式タイムは中断を含む実生活の所要時間ではない。一時停止で考えることまで完全に防ぐ仕様にはせず、停止中の目標表示と入力を抑え、同じ規則で順位を比較する。途中終了では経過時間と到達棟数を示せるが、完走記録・完走称号として登録しない。

### 4.3 保存精度と同順位

| 要件ID | 条件 |
| --- | --- |
| TA-24 | 元の操作時間 `elapsedMs` は0以上の安全な整数ミリ秒で扱う。時計の小数部分は累積してから整数化し、更新ごとに切り捨てない。完成記録では切り上げ前に15000以上であることを検査する |
| TA-25 | 公式記録 `elapsedCs = ceil(elapsedMs / 10)` は100分の1秒単位の整数。表示、順位、自己ベスト、称号、共有はすべてこの値を使う。35.001秒は35.01秒になる |
| TA-26 | 公式記録が同じなら同順位。順位は `1,1,3` とする。同順位の表示順は、その自己ベストを正式記録した日時、最後にプレイIDの順で固定する。表示順の違いを別順位にしない |

通常表示は `01:23.45`、日本語の共有は「1分23秒45」とする。経過時間の表示から独立した通信状態を表示し、記録確定後に秒数が増えないようにする。技術的に扱う上限は `elapsedMs <= 9007199254682991`、`elapsedCs <= 900719925468300` とし、10分を受付上限に転用しない。

## 5. 開始回数・名前・記録の保存

同じ開始や結果を何度送っても1回として扱う仕組み（冪等性）を、端末とサーバーの両方に設ける。単にボタンを無効化するだけで二重登録対策を済ませない。

| 要件ID | 条件 |
| --- | --- |
| TA-27 | 準備が終わり、開始情報を端末へ確定保存した時点を開始成立とし、1回を数える。予約や連打だけでは数えない。取消が先に成立すれば0回、保存確定が先なら直後の非表示・終了でも開始済み1回とする。匿名・名ありで同じ規則を使う |
| TA-28 | 開始を識別する `launchId` は1プレイ1つ。再送・復帰・複数タブからの同じ送信で増えない。同じIDに異なる名前やモードなどを付けた要求は、別プレイへ解釈せず競合として拒否する |
| TA-29 | 公開順位へ登録できるのは、開始時に有効名があり、正式に開始し、30棟完走をサーバーで確認できた記録だけ。匿名記録の後付け命名や、途中終了のタイムは登録しない |
| TA-30 | 完走結果は `resultId` と `playId` によって1つへ固定する。再送しても同じ結果・状態を返す。同じプレイの違う結果で既存記録を上書きしない |
| TA-31 | 名前の同一性は既存 `src/shared/name.js` の規則で比較する。同じ正規化名の最短記録だけを順位表へ出す。同値の新記録は先に確定した自己ベストを置き換えない |
| TA-32 | TAの開始回数と完走登録名数を、通常モードから別に集計する。通常の殿堂入り者もTAへ登録できる。通常殿堂入り人数をTAの人数へ足さない |
| TA-33 | 送信待ちは端末に保ち、同じ宛先・モード・IDで再送する。開始通知を先に送り、その受理後に完走結果を送る。通信失敗時に「登録済み」と表示しない |

名前がある場合、開始前にサーバーへ予約し、出題の元と照合用情報を受け取る。通信できず正式な予約を作れない場合は再試行か、今回だけランキング対象外で始める操作を用意する。対象外を選んだプレイも開始回数には含めるが、後から正式記録へ昇格させない。

開始保存と画面表示は物理的に同時にはできないため、保存確定後に画面を隠した場合は「開始済み・まだ操作時間0」として停止する。最初の目標表示と操作許可の時点から時計を動かす。初回表示前に終了しても開始1回は残す。

匿名も通信の有無にかかわらず開始を端末へ保存し、再接続時に送る。端末保存に失敗した場合は警告を示したうえで、送信できた開始だけをサーバー集計へ反映する。保存が消された端末や再接続しない端末の未送信回数を、サーバーで復元できるとは説明しない。

予約・開始通知・完走結果の再送に、経過日数だけによる自動失効は設けない。明示的に取り消した予約は復活させない。新規のランキング受付を止めても、既存予約の再送、開始済みの通知・結果・状態確認・閲覧は継続する。10分は受付期限にしない。詳細履歴の整理条件と再審査は実装計画§5.7に従う。

通常の途中保存・送信待ちとTAの記録は、端末内のデータベース自体を分ける。旧版のタブにもTAの送信待ちを読ませない。同じ画面で操作するゲームは1つとし、TAの同じプレイを複数タブから更新させない。古い別タブの通常プレイを強制停止できるとは保証せず、保存先の分離で誤送信を防ぐ。モードを切り替えても通常の途中保存を破棄しない。匿名の完走結果と称号・共有は端末側で利用できる。

名前、予約、ログ、結果、開始台帳を専用の非公開領域に保存し、サーバー側で照合してから公開する。結果が確認中か正式か不受理かを区別する。検証担当が停止しても、サーバー側の毎分処理で未処理や期限切れの作業を再取得する。利用者が画面を閉じたことだけで確認中のまま残らないようにする。自動化された入力や端末内の改造をすべて見破れるとは主張しない。サーバーの再計算は、記録と定めたルールの整合性を確かめるためのものとする。

### 6.2 履歴と再計算の約束

履歴時刻 `t` は停止を除いた「操作時間＋移動の実行時間」の整数ミリ秒とする。各イベントに増加する `seq` を付け、同時刻でも順序を保つ。停止・再開は同じ `t` になってよく、どちらも記録する。公式時間はサーバーの状態計算で操作区間だけ積算する。30棟の完走時には `t = elapsedMs + 58000` が成立する。途中終了では、58000の代わりに実行済みの移動時間を使う。

イベント種別・値の範囲・同時刻の順番・明示的な最後の `end` イベントは、実装計画§5.2を正本とする。最後の色入力だけで完走扱いせず、`end` の時刻までの再計算で30棟成立を確認する。

1回の更新で次の目標表示より先に時計を進めない。時刻は棟クリア・移動完了の境界で区切り、不要な入力を新しい棟へ流さない。長い停止時間は `t` に加えない。端末の現在日時の変更によって時計が進んだり戻ったりしない方式を使う。

履歴のUTF-8表現は最大8MiB、分割64片、受信イベント200000件を第1版の運用上限とする。上限へ達してもゲームを10分で打ち切らず、端末の完走タイムと共有は残す。ランキングへ検証可能な履歴を送れない場合は、その理由を表示して未登録とする。開始回数は取り消さない。これらの上限は時間制限とは別に試験する。

同じ作品カードを増やさないため、`public.games` と実験場カタログに別作品の行を追加しない。代表作品 `chameleol` を維持し、`mode_id` によって専用保存・経路・時間表示を区別する。既存のランキング連携形式は、この専用モードの経路を表現できるよう後方互換で拡張する。通常の「棟・降順」を「秒・昇順」で上書きしない。

ランキングの名前は文字として表示し、入力された文字をページの命令として扱わない。参加者が0件、読込中、通信失敗、再試行中をそれぞれ表示する。
